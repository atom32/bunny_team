# UI remake / first playable slice

## Direction

- Variant: off-white / ink / acid yellow (`#E8F34A`), 9px cut corners,
  restrained density, no additional entrance animations.
- Hero: the existing live hideout and operator, not copied Endfield artwork.
- Layout: bold geometric wordmark at entry; quiet, task-focused panels at base.

Inspired by the rules in `hhikr/endfield-ui-skill`, implemented natively in Godot.
No CSS/JS/framework integration and no global skill installation. Saira is the
only new third-party asset; its OFL and provenance are included.

## Functional changes

1. Menu gives game entry clear priority; settings/quit and optional local-only
   feedback remain separate. Suspended sorties retain their original resume path.
2. Base overview separates current request, real credits/extraction count and
   preparation. First-sortie steps are always visible instead of hidden behind
   an ambiguous toggle. Each action uses the existing equipment/data owners.
3. Returning players see actual planned weight and a direct warehouse shortcut.
   Story selection still occurs only after the player activates Continue.
4. Mission review uses the actual selected mission (including first mission),
   puts carry weight first and scrolls long quantities/errors. Invalid deployment
   is visibly disabled with an explanation, while the actual deployment guards
   remain authoritative. No free ammo, extra inventory or automatic progress.
5. Contract records hide conflicting overview actions and restore them on close.
6. Audio sliders show percentages; menu/settings keyboard focus is explicit.

## Scope boundaries

This is the first slice, not a claim that every interface has been redesigned.
Warehouse internals, contacts, combat HUD and results inherit the revised shared
palette but retain their existing structure. Follow-up design work should focus
on warehouse/equipment comparison and packing, then contacts/delivery feedback,
then battle HUD and extraction results. No changes to combat, economy, save schema,
level geometry, character assets or lighting in this pass.

The new composition follows the existing 1280x720 desktop layout. Existing base
tests additionally check 1440x900 and 1920x1080 bounds. Mobile layouts and a new
dark/light preference are not implemented.

## Second slice: warehouse / equipment / packing

- Three explicit areas: equipped gear, base storage, and item inspection or
  sortie packing. The dark header reports actual carried weight, not requested
  stock or a clipped paragraph. Existing base navigation remains unobstructed.
- Single-click a stored or equipped item to inspect it. Equipment comparisons
  use the chosen destination slot; damage, magazine, reload and range come from
  the real definitions. AR upgrades, pellet counts, fitting reload/weight and
  installed fitting descriptions are represented. Armor/backpack comparisons
  show protection, capacity bonus and movement modifier (not guessed total speed).
- Replacement requires an explicit, persistent footer action identifying the
  target slot. It invokes `StashLayout.equip_item`; no alternate inventory or
  equip transaction was introduced. Displaced items return to the storage grid.
  Already-equipped and pending-sortie actions are disabled; the callback also
  checks the pending/live/recovery guards.
- Ammo, medicine and the portable alarm link to their real packing controls.
  Unused calibers explain that a compatible weapon must be equipped first.
  Selecting an item alone never packs, consumes or purchases it.
- Packing keeps requested, packed and owned quantities distinct; shortages use
  signal-yellow fill. Editing preserves compact-panel scroll and keyboard focus.
  Save failure still restores the original request through existing transactions.
- Refresh/language changes retain the chosen right-side tab. New item inspection
  starts at the top, while its confirmation button remains outside the scroller.
- Grid size, manual placement, sort, rotation, drag/drop, equipment popups and
  the existing recovery/packing/data owners were retained.

Validation for this slice is saved in `ui_remake_2026-10-23/warehouse/`:
eight headless regression suites, native base UI clicks (77 checks), native
comparison/equip/packing flow (50 checks, Forward+), and three translation build
tests pass. This includes partial stock, save failures, old/new item identities,
main/secondary swaps and 1280x720 / 1440x900 / 1920x1080 bounds. Screenshots use
controlled finite inventory fixtures; they do not assert earned player progress.
The comparison screenshots isolate the production HangerUI; `workspace.png`
shows the integrated hideout with navigation and mission-terminal entry.

The ammunition UI test now checks the large weight readout plus full tooltip,
and scroll reachability of every quantity field, rather than the replaced clipped
summary and an assumption that all fields fit onscreen simultaneously. All prior
quantity, save-failure and inventory-conservation assertions remain.

No combat HUD or result-flow redesign is included in this second slice.
