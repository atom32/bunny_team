# Neon Bastion 剧情制作包

工作副标题：**别替我签字**。这套稿件把普通人的战区求生、外骨骼依赖与“谁有权替我同意”串成十二章；不是当前 demo 已实现的剧情。

## 结局状态与阶段边界

四项准备与最终执行必须分开记录。**拿到撤销凭据不等于已经撤销权限**：

| 状态 | 类型 / 初始值 | 来源 | 消费者与失效边界 |
|---|---|---|---|
| `case_verified` | bool / false | E04–E10 经主线交叉验证后成立 | Truth；单份未核实文件不足以成立 |
| `independent_care` | bool / false | C10 离线医疗供电、药物与接班医护完成 | True 准备之一；战斗中的暂时断电只暂停进度，不悄悄清除已建立事实 |
| `distributed_evidence` | bool / false | 经患者同意的记录去标识化，三处独立托管完成 | True 与 Truth；保留原始签字链，不公开无关私人病历 |
| `revocation_keys` | bool / false | C11 取得并核对硬件撤销凭据 | True 准备之一，只表示能开始拆除 |
| `evacuation_ready` | bool / false | 双方现场停火、两个出口供电、第一批人实际撤出 | True 准备之一；空口承诺不能置位 |
| `medical_node_detached` | bool / false | C12 切断医疗回收控制，同时维持独立医疗 | True 执行；不能用炸掉患者电源代替 |
| `weapon_authority_revoked` | bool / false | C12 撤销武装执行密钥并停机 | True 执行 |
| `identity_feed_closed` | bool / false | C12 关闭可识别样本回流并确认托管公开 | True 执行 |
| `authority_revoked` | 派生 bool | 上面三个执行状态全部为 true | END_TRUE 最终验收；不可在 C11 提前置位 |
| `bond_sm` | int / 0，范围 0–4 | C02、C05、C09、C10 各一项不可重复的关系事件 | Character，≥3；跳过 fan service 不改变它 |
| `mutual_future` | bool / false | C10 双方明确选择共同生活 | Character 与 True 恋爱后日谈；不靠救命或治疗接触推定 |
| `ending_choice` | enum / none | 明确结局门中的选择 | 一次只选择一种；未满足条件时显示缺项，不降级 |
| `ending_committed` | enum / none | 结局事务成功完成 | 防止重复发结算奖励与结局成就 |

可执行的判定顺序如下，`blocked` 是界面状态而非结局。实现时保留这个顺序，不以“最高好感优先”等隐式规则替代玩家选择：

```text
C05 门：leave_verified -> END_NORMAL；continue_search -> 继续 C06。
C11/C12 门：accept_recovery -> END_BAD（显示明确后果后再次确认选择）。
C12 准备门：
  reject_weapon_role -> 检查 independent_care、distributed_evidence、
                       revocation_keys、evacuation_ready。
                       缺项 -> blocked 并开放补做；齐全 -> B08 第二阶段。
  leave_together -> bond_sm >= 3 且 mutual_future：END_CHARACTER；否则 blocked。
  publish_and_leave -> case_verified 且 distributed_evidence：END_TRUTH；否则 blocked。
  leave_now -> END_NORMAL。
B08 第二阶段出口：
  仍选择 reject_weapon_role 且上述准备成立 且 authority_revoked
  且最后患者撤出 -> END_TRUE；否则继续列出未完成目标。
```

所有 C12 路径先经历共同的设施入口与一次回收封锁，随后分流；只有 True 路径进行三节点拆除和能力逐项退出。Character/Truth/Normal 各有真实离场路径及各自结尾，不共用 True 的毁网镜头后仅替换字幕。

## 存档、跳过与失败

- 每个检查点保存完整场景状态：任务物品、已取普通物品、敌人、门、Boss 部位、关键台词播放标记和所用资源。死亡回滚整个事务，不能只恢复角色血量。
- `started` 与 `committed` 分开：演出中退出，恢复到演出前安全点；已提交后退出，恢复到演出后状态。跳过执行同一个幂等提交函数，不走另一条奖励逻辑。
- 关键证据入日志不占背包空间。普通战利品只通过正常撤离结算；不为了显示“剧情奖励”重复增加已有物品。
- 各分支汇合处保存实际选择并换对白，不抹去后果。线索丢失可由主线备份取得核心事实；额外情报、盟友成本和环境状态仍保留差异。
- 战斗死亡永远是重试。END_BAD 必须由玩家明确交还控制权触发，不使用隐蔽死亡次数阈值。
- 长按跳过、字幕速度、降低闪光/失焦/震动、替代按键与辅助慢行均独立于难度、结局和关系分。切换语言只换文本，不能改变稳定 ID。

## 资产、系统与优先顺序

**第一版可玩的叙事切片**限定 C01：一套原创主角、一个回收员、两类感染者与 B01、扫描机、港口/转运棚模块、十场演出、95 条文本、一个可回滚的检查点系统。商业造型仍须单独制作，当前 Artoria 模型不自动成为原创陆栖的正式资产。

**全篇成本**：主角一名、重要女性配角八名；主要角色共用基础动作库但保留站姿、走路与关键动作；八个 Boss 中三套专门生物/设备资产、三套人物追加装备、两套机械/场景系统；六套环境模块；十八个核心演出与五个可跳过关系片段。每种新增人型都要列出作者、许可、源模型、蒙皮与动画来源；当前 demo 的 Quaternius 人型与 KITE 无人机只是两种已接入的敌人表现，不冒充完整故事敌人表。

**程序依赖**按顺序实施：事件与事务存档 → C01 可通行灰盒 → 对话字幕和控制权 → Boss 部位与真实地形变化 → 两个结局门的灰盒验证 → 全章节内容扩展。不要先实现十二张地图再补事件状态。关系系统只需四个明确事件与一个互相选择，不必引入几十种隐藏性格分。

**音频与镜头**：先用字幕与临时语音验证节奏，再录正式配音；每句仅录规定的主线/分支用途。先做能在游戏相机中看懂的动作，再补近景。没有独立的色情小游戏或依靠衣物撕裂提升伤害的系统。

## 内容验收

文档完整性可检查章节、角色、Boss、镜头、台词与链接 ID；这不能替代故事质量判断。第一次灰盒盲测至少记录：玩家何时意识到被追猎、何时怀疑自己的身份、是否能解释五层真相的差别、是否相信同伴具有自己的目标、以及第一章的哪一个细节在结尾变了含义。

若玩家只记得名词而不记得谁做了什么，优先删解释并补可观察的行动；若玩家认为所有人都是剧本操控的假人，应强化 E11 和至少两次观察系统预测失败的证据。真结局验收必须展示患者、证据与控制权限各自去向，并保留主角失去强化后的可玩离场。
