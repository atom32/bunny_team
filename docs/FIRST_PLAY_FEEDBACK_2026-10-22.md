# 首战准备与本地试玩反馈

## 首战不再带着全空枪卡进教学

首战需要一次真实射击才能开放巡逻、搜刮和撤离。此前把所有兼容弹药请求设成 0，仍可出发，随后只能放弃整套装备。现在按实际装包结果拦截这种出击，提示到沈雁霜处补兼容弹药并检查出击补给；仓库有弹、请求大于 0 或有其他口径都不能冒充实际携带。

只要一把已装备枪有真实兼容弹药即可进入教学，副枪同样有效。这不是保证最低装弹量足够打完整局，也不自动补弹。后续正式区域仍允许合法空枪出击和撤退。旧版本已经保存的空弹教学不改实物或进度，可按原菜单放弃后重新整备；没有偷偷跳课或免费返还装备。

首战失败后的“整备／补给”重建按钮直接打开沈雁霜交易页，能看到替换手枪及原有条件救济入口，不再默认落在唐葵的材料商店。救济资格、价格、失败损失和仓库保护不变。

## 试玩反馈怎样交给开发者

正常菜单、暂停页以及成功／失败结算可打开可选反馈页。填写卡住或无聊的地方、记得的人物／片段／笑点、是否愿意再玩；初始值不预设好评或首次游玩。估计分钟可不填，是玩家自报，不是自动测时或五小时实测。

先看完整 JSON 预览，再主动保存、复制或打开保存文件夹。保存只在本机 `user://feedback` 下创建新的独占目录与报告，失败保留回答，旧报告不覆盖。没有自动联网、上传、打开文件夹或读取完整存档。自动附带字段仅为构建摘要、语言、渲染器、尺寸、场景分类、区域／任务／阶段／状态与返营次数；没有玩家名称、物品／会话 ID、绝对路径或设备标识。自由文本由玩家自行确认，请勿填写个人信息。

报告不会自行发送给开发者。玩家可检查文件后自行分享；愿意再玩不等于平台好评，不能据此宣布达到 80% 目标。

## 构建身份与验证范围

菜单、报告和包旁的 `build_identity.json` 使用按源码清单计算的 `nb-` 摘要，包含未提交源码变化，不拿 Git HEAD 代替实际包；文档改动不改变可玩版本号。开发目录明确显示 development，不假装正式发行。

源验证覆盖严格报告字段、负面回答、中文／Unicode 边界、保存失败与不覆盖、三处实际入口、暂停返回、失败结算及首战装包。测试不实际写剪贴板或打开 Explorer。候选 01 因测试负例字符串被依赖追踪器误认成缺失文件而停止，保留日志；将同值负例改为运行时拼接后生成候选 02，没有放宽依赖检查或创建伪资源。

本轮没有沿用上一轮前台授权，新增反馈页面的原生可读性、键盘滚动、剪贴板与打开文件夹行为仍待实际验看。独立包结果、哈希、包内身份与实际导出报告的对应证明见 [验证记录](first_play_feedback_2026-10-22_validation.json)。仍为本地候选，保留 16 段真实动作及四个独立预览；当前发行资产事项见 [具体核对](RELEASE_ASSET_BLOCKERS_2026-10-22.md)。
