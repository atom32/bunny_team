2026-10-15，接续模型/动作批。现在物品定义由27增至30，新增的是可购买、搜到、携行、安装或出售的套件，不是空定义或新的剧情证据。校园第二批任务仍待继续。

每栈最多4个，占仓库2×1格。教学完成后才开放购买与安装；新存档不赠送。维修区新增快装权重4、消声3，档案区新增观察镜4；原材料权重不变，两处仍以零件/电线或电子元件/电线为主。新增内容不增加物资点或强制剧情随机掉落门槛。

观察镜只扩展信息视野，沿用原视角和墙体射线遮挡，不提高伤害、射程或命中率。消声只改变既有AI听声半径，不消除视线发现、枪口闪光，也不宣称新增了消声录音。

## 实际操作

1. 基地 **联系人 → 苏弥 → 交易 → 购买补给** 买套件，或在校园对应区域搜到后成功带回。
2. 在同一页面的 **武器改装** 选择具体武器、库存套件，查看质量/换弹/听声/观察代价，点击 **安装套件**。
3. 一次消耗一个库存套件，不再收组装费或材料。合格对象仍是单弹丸hitscan枪械；霰弹枪与RPG不适用。每把武器只有一格utility fitting，替换不返还旧改装。
4. 拆除恢复标准配置，不返还套件/材料/信用点；已装的回收套件也可在未恢复工作台时拆除，避免被较慢换弹效果锁住。
5. 组装路线仍在：恢复工作台后，原快装/消声材料改装可继续使用，另有观察镜材料组装。购买/回收成品与工艺解锁是两条不同路径，不修改原有物品或武器数值。

安装只在基地执行，当前出击、挂起出击或恢复错误期间拒绝操作。仓库中的未安装套件不自动加入部署；野外搜到的套件正常占携行重量，成功撤离回仓库。已安装效果写在原武器实例的`fitting`字段，随该实例出击/恢复/回收，死亡或放弃时一起损失；未携行的仓库套件不受影响。

库存套件质量等于安装后的新增质量，从套件转移到武器不会凭空增加总仓库重量；替换会丢掉旧改装的质量。交易先构造候选profile，再原子保存成功后发布，失败不扣钱、不扣套件、不改原武器ID/装备槽/仓库位置。重复点击相同改装不再消耗第二个套件。

## 制作与接口

这3件定义实际通过现有`item_authoring`预览/发布工厂创建，随后配置各自图标、标签、获取池、联系人商店与中英文本。YARD目录同步到30个ID，既有27个ID/UID不改。并非另做一套物品JSON真源。

- `resources/items/material_*_kit.tres`：普通`ItemDefinition`，使用`loot/fitting_kit`标签。
- `WeaponFitting.KITS`将库存ID绑定到单武器改装；`prepare_kit/install_kit`复用原仓库、实例所有权与SaveService事务。
- `PlayerController.get_aim_camera_extension()`供真实Battle镜头与PlayerVisibility共同读取观察镜效果，切到另一把枪立即失去该实例的收益。
- `assets/ui/supply/*_kit.svg`是本项目作者绘制的矢量图标，来源记录见同目录`FITTING_KITS.md`。**没有新增可见枪管/镜片3D附件，也没有修改现有角色/武器模型。**

存档schema7、checkpoint5和校园碰撞/导航布局签名保留。旧改装数据按原规则读取；新内容ID/观察镜枚举不能交给旧版本程序回滚读写，不承诺旧程序的向前兼容。
