## 已实现的物品制作入口

Godot 顶部 **Neon Tools** 新增两项：

- **Audit content / references**：只读报告已注册物品、类型、英文/中文显示名、图标、获取渠道、定义引用及来源许可待审项。检查跨类型重复 ID、重量/占格/堆叠、弹药类型、武器保存握点、敌人/任务/loot/area 数据、配方与 loot 死引用，以及资源文件中的重复 ID/UID、缺失外部路径和未注册定义。
- **Create item / review changes**：选择 Material、Medical、Ammo、Equipment、Weapon 的现有模板，填写新 ID、实际用途、名字、重量/售价/仓库尺寸及来源许可记录。图标与模型先继承模板，创建后通过 Inspector/YARD 继续编辑。

先点击 **预览变更**，查看新文件路径、ID、类型、图标、来源及 manifest 的 `definitions +1`。只有再确认 **创建并注册** 才写入；不覆盖现有文件或复用已有 ID。新文件名使用完整 ID（`.` 转 `_`），而不是只截取最后一段。

发布将新 Resource 与 manifest 分别暂存、校验后改名提交。若源 manifest 或模板在预览后变化则拒绝，普通提交失败回滚新定义；编辑器 UID 的路径也从暂存位置移到最终位置，避免重开时仍查找 `.pending.tres`。**这不是跨两个文件的掉电事务**：硬中断若留下一件未注册新资源，应先检查报告/暂存文件，再决定恢复，不自动覆盖它。

注册只让 ContentDB 在下一次游戏启动加载定义；它不自动增加商店/掉落/配方、中文翻译、动作适配或剧情用途。新装备必须保持不可堆叠，武器仍须使用合法弹药和握点。已有医疗热键/携行入口、敌人 controller 与工作台的固定武器列表也不能凭创建新 ID 自动扩展。

该命令复制 Git 可见 WIP 到隔离副本，冷导入后运行检查，并隔离 APPDATA/LOCALAPPDATA/HOME/XDG_DATA_HOME。主工作区和正常游戏存档不参与运行；输出包括 `content_audit.json`、`results.json`、日志与源文件 hash。存在错误或未完成检查时返回非零退出码；警告保留，不把未知许可当作已确认发行授权。不要以直接 F6 运行工具场景替代隔离命令，因为项目 autoload 会读取该项目的用户目录。
