## 应先处理的五个问题

### P1 第二次出击简报仍指向旧任务和南侧撤离

复现：完成首局，进入基地 Operations，再出击 Streets。基地写“信号回收 / 消灭敌人 / 访问外勤终端 / 南侧撤离信标”，实际任务是档案与庭院调查；本轮分配的两个出口均在北侧。

定位：`D:/bunny_team/scripts/presentation/slice/hideout.gd:110–115`。首局后仍读取 `SortieRequest.PROTOTYPE_MISSION_ID`，并追加固定 south beacon 文案。

建议：简报读取真正要部署的任务；随机出口尚未分配时不要预告固定方向。**不需要改任务或撤离规则。** 对照 `24_second_sortie_briefing.png` 与 `31_streets_map_input.png`。

### P2 失败结算把带回物资当作阵亡时物资

复现：携带 AR/RPG 等装备进入 Streets，正常阵亡。界面显示“阵亡时负重 0.0 / 100.0 kg”“阵亡时携带物品 0”；该局 session 实际仍记录 21.372 kg。

定位：`D:/bunny_team/scripts/ui/result_ui.gd:113–118` 读取 `outcome.inventory`。`D:/bunny_team/scripts/data/sortie_outcome.gd:61–67` 在失败时有意创建空的回收库存，因此“未带回物品”正确，但“阵亡时负重”的标签与数据不匹配。

建议：保留失败回收语义，纠正标签；如果必须显示阵亡快照，再独立设计只读统计。证据 `29_defeat_result.png/json`。

### P2 机库仓库覆盖角色和武器展示

复现：基地进入 Hanger，等待镜头过渡完成。仓库面板占据左中部，装备面板占右部；角色身体几乎完全被覆盖，只明显露出兔耳，换装难以直观看到结果。

建议：执行已有的“基地角色展示与仓库屏幕分离”方案，或折叠仓库并留出清晰预览区。不要靠改人物比例补偿 UI。证据 `51_hanger_settled.png`，不是过渡中的暗帧。

### P2 战斗角色与入口遮挡的可读性不足

生产战斗镜头下人物很小，细部和手持武器难辨；首局 Field Office 门口战斗时，门楣/雨棚遮住角色上半身，主要靠脚下圆环判断位置。室内世界文字也明显小于 HUD。

建议先检查遮挡淡出覆盖范围、镜头距离与目标提示。不能由这些远景截图推断角色腿长或几何比例错误，更不应改角色网格。证据 `13_smg_alarm_combat.png` 与 `41_rpg_reloaded.png`。这是画面阅读问题，未发现因此卡住交互路线。

### P2 多个 PMC 追击后几乎完全重叠

Streets 庭院战斗时，三个存活 PMC 聚集到近乎相同位置，画面像一个敌人，实际仍是多个单位。记录的两两距离为 **0.45–1.05 毫米**，不只是镜头投影造成的重叠。

证据 `enemy_overlap.json` 和 `41_rpg_reloaded.png/json`。复现条件为多个 PMC 沿相同追击路线靠近庭院；尚未归因到具体避让/碰撞实现。建议单独检查敌人占位与分离，不在本轮改 AI。

## 性能观察不是性能认证

未暂停的战斗遥测中，首局 498 个一秒采样的 FPS 中位数 60、p05 为 59；Streets 两次尝试共 226 个采样，中位数 60、p05 为 44。Streets 最大 draw calls 3290，Godot 渲染显存计数约 857 MiB。
